# Картотека выдач: ООП (лабораторные 1-10) и Web-программирование (лабораторные 1-9)

Одно приложение вместо 19 отдельных проектов. Предметная область та же, что в курсовой работе по ООП:
библиотека, читатели, выдачи книг. Каждая следующая лабораторная работа дорабатывает предыдущую,
поэтому в репозитории собран итог всей цепочки: окно Swing (курс ООП) и сайт на Tomcat (курс Web)
работают с одним и тем же набором данных. Запись, добавленная на сайте, сразу появляется в таблице Swing, и наоборот.

Автор: Рябов И.А., группа 5315.

## Запуск

Нужна Java 17 или новее (проверено на Java 25). Maven ставить не нужно, есть обёртка `mvnw`.
Команды выполняются из корня репозитория.

Windows:

```bat
run.bat
```

Linux и macOS:

```sh
./run.sh
```

Скрипт собирает проект и запускает один процесс, который:

* открывает окно Swing «Картотека выдач» (ООП 1-10);
* запускает встроенный Tomcat: сайт на http://localhost:8080/ и HTTPS на https://localhost:8443/ (Web 1-9).

Только сайт, без окна: `run.bat --no-gui`. Другие порты: `-Dhttp.port=9090`.

Учётные записи для входа на сайт:

| Пользователь | Пароль | Роль |
|---|---|---|
| `librarian` | `lib123` | библиотекарь: смотрит, добавляет, изменяет, удаляет |
| `reader` | `read123` | читатель: только смотрит |

Подробный разбор каждой работы: [docs/LABS.md](docs/LABS.md). Запуск в Eclipse: [docs/ECLIPSE.md](docs/ECLIPSE.md).

Тесты: `./mvnw test` (28 тестов: JUnit 5 и Mockito). Документация Javadoc: `./mvnw javadoc:javadoc`,
результат в `target/reports/apidocs`. Файл для отдельного Tomcat (Web 2): `./mvnw package`, результат `target/issues.war`.

## Где смотреть каждую лабораторную работу

### ООП (окно Swing)

| № | Тема | Где в приложении | Код |
|---|---|---|---|
| 1 | Среда разработки, консольное приложение | Меню «Сервис», «Сортировка массива»; из консоли: `java -cp target/classes edu.java.issues.lab1.ArraySort` | `lab1/ArraySort.java` |
| 2 | Интерфейс пользователя | Окно: меню, панель инструментов с иконками, таблица, панель поиска, журнал | `ui/IssueListForm.show()` |
| 3 | Обработка событий | Кнопки, выбор читателя в списке (строка состояния), двойной щелчок по строке (карточка выдачи), закрытие окна | `ui/IssueListForm.addListeners()` |
| 4 | Исключения | «Поиск» с пустым условием или названием из одного символа | `exception/EmptyQueryException`, `ShortNameException`, `model/IssueRepository.checkQuery` |
| 5 | Файлы | Кнопки «Открыть» и «Сохранить» с файлом `.txt` (`data/issues.txt`) | `io/TextIssueStorage` |
| 6 | XML | Те же кнопки с файлом `.xml` (`data/issues.xml`), разбор и построение через DOM | `io/XmlIssueStorage` |
| 7 | Отчёты PDF и HTML | Кнопка с принтером или меню «Отчёты»: два шаблона JasperReports, результат в `reports/out/` | `report/IssueReportBuilder`, `src/main/resources/reports/*.jrxml` |
| 8 | Потоки | Меню «Потоки», «Запустить конвейер»: три потока ждут друг друга через wait/notifyAll, ход виден в журнале | `concurrent/ReportPipeline` |
| 9 | Модульные тесты | `./mvnw test` | `src/test/java` |
| 10 | Протоколирование | Нижняя часть окна и файл `logs/issues.log`; настройка в `log4j2.properties` | `ui/SwingLogAppender`, `log4j2.properties` |

| № | Тема | Где на сайте | Код |

## План записи видео (около 6 минут)

1. `run.bat`: появляется окно Swing и в консоли адрес сайта. Показать таблицу и журнал внизу (ООП 2, 10).
2. Поиск без условий и по названию «А»: два окна с исключениями (ООП 4). Поиск «мир» и выбор читателя (ООП 3).
3. Сохранить в `.txt`, открыть заново; сохранить в `.xml`, открыть заново (ООП 5, 6).
4. «Отчёты»: открываются HTML и PDF (ООП 7). «Потоки»: в журнале видно, как потоки ждут друг друга (ООП 8).
5. «Сервис», «Сортировка массива» (ООП 1).
6. Браузер: главная страница с картой лабораторных, переключить RU и EN (Web 4).
7. Войти как `reader`: изменить ничего нельзя; выйти, войти как `librarian` (Web 6).
8. Добавить выдачу на сайте и показать, что она появилась в таблице Swing (общее хранилище).
9. «Выбор читателя», затем «Выдачи» (Web 7). «Версия на сервлете» (Web 3). «GWT» (Web 8).
10. Терминал: `./mvnw test`, 28 тестов зелёные (ООП 9, Web 9).

## Сборка клиента GWT

Готовый JavaScript лежит в `src/main/webapp/gwt-app`, поэтому GWT-компилятор для запуска не нужен.
Чтобы пересобрать клиентскую часть после правок в `gwt/client`:

```sh
./mvnw -Pgwt -DskipEcj net.ltgt.gwt.maven:gwt-maven-plugin:1.1.0:compile
```

`-DskipEcj` отключает новый компилятор JSP на время сборки: у GWT собственный JDT, и они конфликтуют.

## Замечания по безопасности

* Пароли демонстрационных пользователей хранятся в виде хеша PBKDF2 с солью, но сами пароли указаны выше
  в открытом виде: это учебное приложение. Для реального использования их нужно заменить.
* Сертификат HTTPS (`conf/keystore.p12`, пароль `changeit`) самоподписанный и создан для localhost.
  Браузер покажет предупреждение, его нужно подтвердить вручную.
* Формы изменения данных защищены токеном, весь вывод экранируется, XML читается без DTD и внешних сущностей.
